Mouse input: what's actually happening

Setting MouseSpeed, MouseThreshold1 and MouseThreshold2 to 0 is precisely what the "Enhance pointer precision" checkbox in Windows' mouse settings controls — off means flat, linear response with no acceleration curve applied. This is the standard, Microsoft-documented way to disable pointer acceleration, not a third-party trick.

WORTH KNOWING The same section also defines custom SmoothMouseXCurve / SmoothMouseYCurve values — but those curve tables are only consulted by Windows when MouseSpeed is 1 (Enhance Pointer Precision on). With MouseSpeed already set to 0 here, Windows applies flat scaling directly and doesn't read the curve table at all. The linear-response result you get is coming from MouseSpeed=0 alone — the custom curve data alongside it is inert, not harmful, just not doing anything on its own.

The buffer size increase (MouseDataQueueSize / KeyboardDataQueueSize raised from Windows' default of 100 to 150) gives the input driver more room to queue reports before overflowing. It only matters if you're seeing dropped inputs during very fast movement on a high-polling-rate mouse — it's queue depth, not added delay, so it doesn't cost you latency to set it higher.

MMCSS: scheduling priority for games

The Multimedia Class Scheduler Service was originally built to stop background CPU load from causing audio glitches, by giving registered threads guaranteed scheduling priority. The Tasks\Games profile this section edits is one of several built-in task categories MMCSS uses — Windows' own scheduling hooks (including Game Mode) consult it for the process currently in focus. Not every game or emulator explicitly opts into this category, so real-world impact varies by title and is genuinely difficult to measure in isolation from everything else changed here.

Power, USB and memory tuning

Locking CPU min/max P-state at 100% (Section 11) stops the processor from clocking down at all, even briefly at idle — zero ramp-up latency when load appears, at the cost of more heat, fan noise, and power draw around the clock. On a desktop with adequate cooling that's a fair trade for some; on a laptop it means the fan never really goes quiet and battery life drops noticeably even sitting at the desktop.

Disabling USB selective suspend (Section 5) stops Windows power-managing USB ports into a low-power state, which can otherwise cause a brief hitch the moment a port wakes back up — relevant mainly for wired, high-polling-rate mice.

DisablePagingExecutive and the increased IoPageLockLimit (Section 8) keep more kernel code pinned in RAM instead of eligible to be paged to disk. This mattered more when spinning hard drives were common; on a modern system with 16GB+ RAM and an NVMe SSD, the practical difference is small.

The one line that's a security trade-off, not a performance one

SECTION 13 — READ THIS ONE FeatureSettingsOverride / FeatureSettingsOverrideMask set to 3 disables the CPU-level Spectre (branch target injection) and Meltdown (rogue data cache load) mitigations Microsoft shipped starting in early 2018. These mitigations carry a real, measurable overhead — more pronounced on older CPU generations and I/O-heavy workloads — so disabling them does recover some performance. But what they protect against is one process or privilege level reading memory it shouldn't. The practical exposure mainly shows up when untrusted or sandboxed code runs alongside anything sensitive — browser tabs, VMs, containers, a shared or multi-user machine. The script's own comment says this isn't recommended on a machine used for banking or sensitive work; that's the actual dividing line, not a formality to skip past.

Emulator process priority

The Image File Execution Options entries for LDPlayer, BlueStacks, HD-Player, MEmu and Nox set CPU/IO/page priority automatically whenever those processes launch — the equivalent of manually setting "High priority" in Task Manager every time, made persistent. It only helps as much as the emulator's own settings (allocated CPU cores and RAM in its own configuration panel) allow — this doesn't substitute for those being set sensibly first.

How to apply it

  1. Right-click the .reg file → Merge, accept the UAC prompt.
  2. Open Command Prompt as Administrator and run all four of: 
    bcdedit /set useplatformclock false
bcdedit /set disabledynamictick yes
bcdedit /set tscsyncpolicy enhanced
powercfg /setactive 8c5e7fda-e8bf-4a96-9a85-a6e23a8c635c
  3. Reboot before judging any result — several of these (timer resolution, P-state) only take effect after a restart.

These four commands set Boot Configuration Data, a different subsystem from the registry — that's why they can't be folded into the .reg file itself and need to be run separately.

FAQ

Is this reversible?

Mostly. The Spectre/Meltdown override and the CPU P-state lock are single-value flips back to their Windows defaults. Full reversal of every key is easiest by importing a fresh export of the same registry paths from an unmodified machine, or resetting each section manually.

Will this work well on a laptop?

Several settings here — the CPU P-state lock and disabled USB power saving especially — are meaningfully different trade-offs on battery power. This was written with a desktop in mind; expect more heat, fan noise and battery drain if you run it on a laptop.

Do the bcdedit commands really need to be run separately?

Yes — they modify Boot Configuration Data, not the registry, so a .reg file has no way to set them.
