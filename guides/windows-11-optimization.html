Windows 11 Deep Optimization: what changed from Windows 10, and what got riskier

The Windows 11 script deletes several services outright instead of disabling them — including two your system depends on more than you'd expect.

Same idea, sharper edges

This script covers the same ground as the Windows 10 Optimization script — telemetry, Cortana, OneDrive, Xbox services, Game DVR, visual effects, power and network tuning — rebuilt for Windows 11's service set, plus Widgets and the taskbar Chat icon. The mechanism/why for those shared settings is covered in that guide rather than repeated here; this page focuses on what's actually different.

Delete vs. disable — why it matters

The Windows 10 script uses sc config <service> start= disabled for the services it turns off — the service stays registered, and flipping start= back to demand or auto restores it in one command. This script uses sc delete for several services instead, which removes the service's registry entry under HKLM\SYSTEM\CurrentControlSet\Services entirely. Windows won't just recreate that on its own — getting a deleted built-in service back generally means sfc /scannow, DISM /Online /Cleanup-Image /RestoreHealth, or waiting for the next feature update to rebuild it. That's a meaningfully bigger step than the Windows 10 script asks you to take.

The two deletions worth knowing about first

WSearch This is the Windows Search service — it powers the Start menu's search box and File Explorer's search/index. Deleting it means typing into Start stops returning app and file results. If you use Start search regularly, this is an immediately noticeable change, not a background one.
BITS Background Intelligent Transfer Service handles resumable background downloads — and Windows Update itself leans on it for background transfers, alongside Windows Defender definition updates and some game launchers. Worth noting: this same script sets wuauserv to manual/demand-start rather than disabling it outright, which only makes sense if Windows Update is still expected to work on demand — but deleting BITS undercuts exactly the mechanism Update needs for that. If you want Windows Update to keep functioning at all, either skip the BITS deletion line or change it to sc config BITS start= disabled instead of sc delete.

Everything else

Search Indexer (WSearch, disabled separately from the delete step above in some builds) and SysMain (Superfetch) are turned off to cut background RAM/CPU use — SysMain's job is pre-loading frequently used apps into memory, which costs some idle RAM in exchange for faster launches; disabling it trades that away. CPU P-state is locked at 100% min/max via powercfg, similar in effect to the Windows 10 script's High Performance plan but set more explicitly at the processor level. Game DVR and Widgets/Chat are disabled the same way as their Windows 10 counterparts.

FAQ

Start menu search stopped working after I ran this — why?

Almost certainly the WSearch deletion above. The safe fix is sfc /scannow followed by DISM /Online /Cleanup-Image /RestoreHealth, rather than trying to hand-recreate the service entry — built-in service registration has enough moving parts (image path, dependencies, service type) that a manual sc create is easy to get subtly wrong.

Windows Update won't check for updates anymore — is that this script?

Likely the BITS deletion combined with Update set to manual. Same fix as above (SFC/DISM), or avoid deleting BITS in the first place.

Is this reversible?

The disabled services and registry values, yes. The deleted services (BITS, WSearch, and the others removed with sc delete) need a system file repair rather than a simple setting flip.
