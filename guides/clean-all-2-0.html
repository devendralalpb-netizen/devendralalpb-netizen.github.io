What actually fills these folders up

Most of what this script removes isn't the result of anything unusual you did — it's the normal byproduct of software that doesn't clean up after itself. Installers and updaters drop working files into %TEMP% and rarely delete them once they're done. Windows' thumbnail cache exists so File Explorer doesn't have to re-render a preview every time you open a folder full of images or videos; it regenerates automatically the moment it's missing, so deleting it is never destructive, just temporary.

Browser "code cache" is a separate thing from your browsing history or downloads — it's compiled JavaScript bytecode Chromium-based browsers keep around so sites you revisit don't have to be recompiled from scratch. Clearing it costs you a slightly slower first load on your next few visits, nothing more. Game cache folders (Steam's htmlcache, the Epic Games Launcher's web cache) are the same idea applied to a store client's embedded browser, not your actual game installs or saves.

The one that surprises people is Windows Update's SoftwareDistribution folder. Every cumulative update leaves its downloaded payload behind after installing, and on a machine that's gone a few years without a full reset of that folder, it can grow into several gigabytes of files Windows will never need again.

Walking through the 14 steps

The script groups into four real phases, even though it's numbered as 14 flat steps.

1. Ownership and permissions (steps 1)

takeown /f ... /r /d y forces the current admin account to own a folder tree before deleting from it. This matters when a previous install, a crashed updater, or a different user profile left files behind with permissions that don't include your current account — without this step, some of the later delete commands would silently skip those files.

2. The temp & cache sweep (steps 2–6, 9–10)

Recycle Bin, Windows and user TEMP, the thumbnail cache, and browser/game caches all get cleared here. Explorer is killed and restarted mid-way through (step 5) specifically because thumbcache_*.db files are locked open by Explorer while it's running — you can't delete a file that's in use, so it has to go down briefly first.

WORTH KNOWING Step 9 clears cache for Chrome, Edge and Brave by targeting their specific Code Cache subfolder — cache only. The Firefox line doesn't do the same scoping: it targets ...\Mozilla\Firefox\Profiles\* directly and recursively. That's the folder holding bookmarks, saved logins, browsing history and extensions, not just cache. If you use Firefox, that line will wipe more than you probably intend. Removing that single line (or backing up your Firefox profile first) is the safe move until it's rescoped to a cache-only path.

3. The Windows Update reset (steps 12, 14)

Deleting SoftwareDistribution while the update services are still running risks leaving Windows Update in a half-broken state, since those services can be mid-write to that folder. Stopping wuauserv, bits, dosvc and UsoSvc first, then wiping the folder, then restarting the same services, is the standard safe order — Windows rebuilds the folder from scratch the next time it checks for updates.

4. Disk Cleanup, with a catch (step 13)

cleanmgr.exe /sagerun:50 runs whatever cleanup categories were saved under profile "50." That profile only exists if cleanmgr /sageset:50 was run at least once on that machine to pick which categories to include. If it's never been set up, this step opens and closes Disk Cleanup without actually removing anything — not a bug in the script, just a step that needs a one-time setup to do anything. Run cleanmgr /sageset:50 once, tick the categories you want, and this step starts pulling real weight.

What this won't do

Temp and cache files are usually measured in tens or low hundreds of megabytes, not gigabytes — this script won't rescue a drive that's actually full of games, videos or installers. On a fast NVMe SSD, the performance difference is generally not something you'll feel. Where it genuinely helps: a drive that's nearly out of space, or troubleshooting flaky Explorer/Windows Update behavior where a stale cache is a plausible cause.

FAQ

Will this touch my Steam library or game saves?

No. The game-related lines target launcher web caches (Steam's htmlcache, Epic's launcher webcache, Roblox downloads folder) — none of these are your installed games or save files.

Why did my open windows and taskbar flash?

Step 5 restarts explorer.exe to release its lock on the thumbnail cache file. It's cosmetic — open folder windows may flicker or briefly close, then Explorer comes back.

Does it need Administrator rights?

Yes. The script checks for an active admin session and re-launches itself with a UAC prompt if it isn't already elevated.
